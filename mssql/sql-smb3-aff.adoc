[role="lead"]
NetApp AFFシステム上のSMB 3の継続的に利用可能な共有にユーザーデータベース、トランザクションログ、TempDB、およびバックアップを配置して、Windows Server 2025上にSQL Server 2025をデプロイします。この手順には、ONTAP SVM、ボリューム、および共有を設定し、その後SQL Serverをインストールする作業が含まれます。



[[scope]]
[[intro-scope]]
== Scope

この手順では、単一の Windows Server 2025 ホスト上にスタンドアロンの SQL Server 2025 インスタンスをデプロイし、ユーザーデータベース、トランザクションログ、TempDB、およびバックアップを SMB 3 の継続的可用性（CA）共有に配置します。同じストレージ設計は、SQL Server フェールオーバー クラスター インスタンス（FCI）および Always On 可用性グループにも適用されますが、クラスター固有の構成については説明しません。SQL Serverのパフォーマンスチューニングとサイジングも対象外です。メリット、解決策の構成要素、設計原則、および継続的可用性の仕組みの説明については、link:sql-smb3-aff-overview.html["SMB 3の継続的な可用性を備えたNetApp AFF上のSQL Server 2025について学ぶ"] を参照してください。



[[audience]]
[[intro-audience]]
== 観客

この手順の対象者は次のとおりです：

* *ストレージ管理者*は、ONTAPクラスタ、SVM、ボリューム、およびSMB共有を設定します。
* Windows Server 2025 ホスト、サービス アカウント、およびネットワークを準備する *Windows および Active Directory 管理者*。
* *データベース管理者*は、SQL Server 2025をインストールおよび構成し、バックアップとリカバリを設定します。


ONTAP System Manager、Windows Server、およびSQL Serverの管理に関する基本的な知識があることを前提としています。

| `sql1_data` | 1024 GiB | `+\\a50-sql\sql1_data+` | ユーザーデータベースデータファイル(`.mdf`、 `.ndf`）

[[prerequisites]]
== 前提条件

開始する前に、以下の要件を満たしていることを確認してください：

.NetApp ONTAP
* AFF HAペアがインストールされ、クラスターがセットアップされ、正常に動作しています。
* CIFS（SMB）ライセンスがインストールされています。ONTAP Oneに含まれています。
* 各ノードに少なくとも1つのデータ アグリゲート（ローカル層）が存在します。
* クラスターとActive Directory間の時刻はNTPを介して同期されます。Kerberosで許容される最大クロックスキューは5分です。
* SMB LIF用のデータネットワークポート、ブロードキャストドメイン、および（オプションで）VLANが設定されます。


.Active DirectoryとDNS
* Active Directoryドメインが利用可能であり、SVMデータLIFからDNSサーバーにアクセスできます。
* CIFSサーバー用のターゲットOUにコンピューターオブジェクトを作成する権限を持つアカウントをお持ちです。
* SQL ServerデータベースエンジンおよびSQL Serverエージェントサービスには、サービスアカウントとして専用のドメインユーザーアカウントが用意されています。



IMPORTANT: SQL ServerのファイルがSMB共有上にある場合、SQL Serverは*ドメインアカウント*で実行する必要があります。組み込みの仮想アカウント(`NT SERVICE\MSSQLSERVER`）およびローカルアカウントには、リモートファイル共有へのアクセス権を付与できません。

.Windows Server
* Windows Server 2025（デスクトップエクスペリエンス）がインストールされ、パッチが適用され、ドメインに参加しています。
* SQL Server 2025のインストールメディア（ISO）と有効なプロダクトキー（または無料版）をご用意ください。


.ONTAP 上の SQL Server に対する SMB の要件と制限事項
* SVM上でSMB 3.0以降を有効にする必要があります。
* CA共有をホストするすべてのボリュームは、*NTFS*セキュリティスタイルを使用する必要があり、最初からNTFSである必要があります。
* SMB Direct（RDMA）はサポートされていません。
* ReFSはサポートされていません。ONTAP（WAFL）は共有用のファイルシステムを提供します。

SQL Serverには専用のSVMを使用してください。SVMはCIFSサーバーとしてActive Directoryに参加し、HAペアの各ノードに1つのSMBデータLIFを提供します。

.手順
. System ManagerまたはCLIを使用してSVMを作成します：
+
[role="tabbed-block"]
====
.System Manager
--
.. System Managerで、menu:Cluster[Storage VMs]に移動し、*+ Add*をクリックします。
+
.例を表示
[%collapsible]
=====
image:sql25_smb_bp_006.png["クラスタ > ストレージVM > 追加"]

=====
.. *ストレージVM名* `a50-sql`を入力します。*アクセスプロトコル*で、*SMB/CIFS、NFS、S3*タブを選択し、*SMB/CIFSを有効にする*を選択します。
+
.例を表示
[%collapsible]
=====
image:sql25_smb_bp_007.png["ストレージVMの追加 - 名前とプロトコル"]

=====
+

NOTE: ストレージVM名は、CIFSサーバーのSMB名です。

.. Active Directoryの情報（ドメイン、管理者名とパスワード、OU）とDNS情報（DNSドメインとネームサーバー）を入力してください。
.. *ネットワークインターフェース*で、*各*ノードに1つのデータLIFを設定します。
+

TIP: ノードごとに1つのLIFを用意することで、SQL Serverは各ノードへの直接的な（ローカル）パスを取得でき、これはSMBマルチチャネルおよび無停止フェイルオーバーの前提条件となります。25 GbE以上のポートを使用し、エンドツーエンドで同じMTUを使用してください。

+

NOTE: これらのネットワークインターフェイスをDNSサーバーに登録する必要があります。詳細については、 https://docs.netapp.com/us-en/ontap-system-manager-classic/smb-config/task_mapping_smb_server_dns_server.html["SMBサーバーをDNSサーバーにマッピングする"^]を参照してください。

.. *保存*をクリックします。System Managerは、SVM、ルートボリューム、LIF、およびDNS構成を作成し、CIFSサーバーをドメインに参加させます。
.. ラボのSVMルートボリューム(`a50_sql_root`を確認します）。そうしないとSMB共有が機能しなくなるため、*NTFS*セキュリティスタイルを使用する必要があります。menu:Storage[Volumes]に移動し、ルートボリュームを選択して、*Edit*をクリックし、その設定を確認します。
+
.例を表示
[%collapsible]
=====
image:sql25_smb_bp_012.png["SVMルートボリュームa50_sql_rootを編集します"]

=====


--
.ONTAP CLI
--
以下のコマンドは、CLIから同じ設定を作成します。山括弧内のプレースホルダー値を置き換えてください。

[source, console]
----
cluster::> vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs

cluster::> vserver modify -vserver a50-sql -allowed-protocols cifs

cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
cluster::> network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

cluster::> vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>

cluster::> vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers
----
--
====
. [[svm-smb-options,SMBサーバーオプションの設定]]SMBサーバーオプションを設定します。SVMでSQL Serverに必要なSMBオプションが有効になっていることを確認します：
+
[source, console]
----
cluster::> set -privilege advanced
cluster::*> vserver cifs options show -vserver a50-sql -fields smb3-enabled,is-multichannel-enabled,is-large-mtu-enabled,copy-offload-enabled,shadowcopy-enabled
cluster::*> vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
cluster::*> set -privilege admin
----
+
[cols="1,3"]
|===
| オプション | 目的 


| `smb3-enabled` | 継続的に利用可能な共有には、SMB 3.xが必要です。 


| `is-multichannel-enabled` | SMBマルチチャネルは、スループットと耐障害性を向上させるために、複数のTCP接続とネットワークパスを使用します。 


| `is-large-mtu-enabled` | SMBによる最大1MBまでの読み書きを許可します。 


| `copy-offload-enabled` | ODXコピー オフロード；コピーはストレージシステム内部で実行されます。 


| `shadowcopy-enabled` | SMB共有用のリモートVSS。SMB共有にVSSを使用するバックアップアプリケーションに必要です。 
|===
. CIFSサーバーがDNSに登録されており、SQL Serverホストから名前解決できることを確認してください：
+
[source, powershell]
----
PS C:\> Resolve-DnsName a50-sql.sapcc.stl.netapp.com
----

== ステップ4：ボリューム設定を調整します

各SQL Serverボリュームの容量設定とスナップショット設定を確認し、必要に応じて調整してください。

.手順
. ボリュームリストで、ボリュームにカーソルを合わせ、鉛筆アイコン（*編集*）をクリックします。
+
.例を表示
[%collapsible]
====
image:sql25_smb_bp_023.png["ボリュームリストの編集アイコン"]

====
. ボリュームを次のように構成します（ `sql1_data`の場合）：
+
** *シンプロビジョニングを有効にする*：選択済み
** *自動サイズ変更*：選択済み、*自動拡大モード*：*拡大*、*最大サイズ*：たとえば `1.3 TiB`（ボリュームサイズの約125～130%）
** *フラクショナルリザーブを有効にする（100%）*：クリア
** *セキュリティの種類*： `NTFS`
** *Snapshotリザーブ%*： `5` (`0` のために `sql1_tempdb`）
** *スケジュールされたスナップショット*：クリアされました。アプリケーションと整合性のないスナップショットは SQL Server では役に立ちません。代わりに NetApp SnapCenter を使用してください（<<references>> を参照）。
** *スナップショットディレクトリをクライアントに表示する*：オプション（ラボでは選択したままにしています。選択を解除すると共有から `~snapshot`が非表示になります）
+
*「保存」*をクリックし、 `sql1_log`、 `sql1_tempdb`、および `sql1_backups`についても繰り返します。

+
.例を表示
[%collapsible]
====
image:sql25_smb_bp_024.png["ボリュームsql1_dataの設定を編集、width=450"]

====

----
cluster::> volume modify -vserver a50-sql -volume sql1_data -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 1.3TB
----

[[step-5-enable-continuous-availability-on-the-smb-shares]]
[[ca-shares]]
== ステップ5：SMB共有で継続的な可用性を有効にする

SMB上のSQL Serverにとって、継続的な可用性は最も重要な設定です。これがないと、ONTAPのテイクオーバーやLIFの移行中にSQL Serverが開いているファイルハンドルを失い、データベースがsuspect状態になります。

.手順
. System ManagerまたはCLIを使用して、SMB共有の継続的な可用性を有効にします：
+
[role="tabbed-block"]
====
.System Manager
--
.. menu:Storage[SMB shares]に移動します。リストには、4つの新しい共有とデフォルトの管理共有 `c$`および `ipc$`が表示されます。
+
.例を表示
[%collapsible]
=====
image::sql25_smb_bp_025.png[SMB共有リスト]

=====
.. 共有 `sql1_data`の横にある「その他」アイコン（*⋮*）をクリックし、*編集*を選択します。
+
.例を表示
[%collapsible]
=====
image::sql25_smb_bp_026.png[「編集」を含む「共有」コンテキストメニュー]

=====
.. *共有プロパティ*で、以下を設定します：
+
*** *継続的な可用性を有効にする*：*選択済み*
*** *クライアントがスナップショットディレクトリにアクセスできるようにする*：クリア済み
*** *この共有フォルダへのアクセス中にデータを暗号化する*：クリア（セキュリティ要件に応じて任意で選択可能）
*** *oplockを有効にする*：選択済み
*** *変更通知を有効にする*：選択済み
*** *アクセスベースの列挙（ABE）を有効にする*：クリア済み
+
*保存*をクリックします。

+
.例を表示
[%collapsible]
=====
image::sql25_smb_bp_027.png[継続的な可用性を有効にした共有を編集します]

=====


..  `sql1_log`、 `sql1_tempdb`、および `sql1_backups`について、これらの手順を繰り返します。

.ONTAP CLI

[[step-6-prepare-windows-server-2025]]
[[windows-prep]]
== ステップ6：Windows Server 2025を準備する

ドメイン管理者として、SQL Serverホスト `{host}`で次の手順を実行します。

.手順
. サーバーがドメインに参加していること、およびCIFSサーバーが解決できることを確認してください（<<svm-smb-options>> を参照）。
. たとえば、SQL Server サービス アカウントが Active Directory に存在することを確認してください `SAPCC\sql1admin`。Database Engine と SQL Server Agent に同じアカウントを使用するか、それぞれに別のアカウントを使用してください。どちらを選択するにしても、各アカウントに4つの共有すべてへのアクセス権を付与してください。
. サービスアカウントのセキュリティコンテキストで、共有フォルダへのアクセスをテストします：
+
[source, powershell]
----
PS C:\> runas /user:SAPCC\sql1admin "cmd /c dir \\a50-sql\sql1_data && echo test > \\a50-sql\sql1_data\write-test.txt && del \\a50-sql\sql1_data\write-test.txt"
----
. WindowsファイアウォールでSQL Serverのポートを開放してください：
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. SVMへのSMB接続を確認します。ダイアレクトは3.xであり、 `ContinuouslyAvailable`は `True`である必要があります：
+
[source, powershell]
----
PS C:\> dir \\a50-sql\sql1_data | Out-Null
PS C:\> Get-SmbConnection -ServerName a50-sql | Format-Table ServerName,ShareName,Dialect,ContinuouslyAvailable,Encrypted,Signed
PS C:\> Get-SmbMultichannelConnection -ServerName a50-sql
----



NOTE: デフォルトでは、Windows Server 2025はすべての送信SMB接続にSMB署名を要求します。ONTAPはSMB署名をサポートし、自動的にネゴシエーションを行います。署名は双方にCPUオーバーヘッドを追加するため、パフォーマンス テストに含めてください。セキュリティ レビューなしで署名を無効にしないでください。

+
.例を表示
[%collapsible]
====
image:sql25_smb_bp_047.png["UNCパスを含む新しいデータベースダイアログ,width=800"]

====

+
.例を表示
[%collapsible]

[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
== ONTAP CLIスクリプトを使用して、ストレージを一度に構成します

以下のスクリプトには、この手順で取得したストレージ構成がすべて含まれています。実行する前に、山括弧内の値を置き換えてください。

[source, console]
----
# --- SVM -----------------------------------------------------------------
vserver create -vserver a50-sql -rootvolume a50_sql_root -aggregate <aggr_node1> -rootvolume-security-style ntfs
vserver modify -vserver a50-sql -allowed-protocols cifs

network interface create -vserver a50-sql -lif a50-sql_smb_n1 -service-policy default-data-files -home-node <node1> -home-port <port> -address 192.168.175.138 -netmask <netmask>
network interface create -vserver a50-sql -lif a50-sql_smb_n2 -service-policy default-data-files -home-node <node2> -home-port <port> -address 192.168.175.139 -netmask <netmask>

vserver services name-service dns create -vserver a50-sql -domains sapcc.stl.netapp.com -name-servers <dns1>,<dns2>
vserver cifs create -vserver a50-sql -cifs-server A50-SQL -domain sapcc.stl.netapp.com -ou CN=Computers

set -privilege advanced
vserver cifs options modify -vserver a50-sql -smb3-enabled true -is-multichannel-enabled true -is-large-mtu-enabled true -copy-offload-enabled true -shadowcopy-enabled true
set -privilege admin

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql1_data    -aggregate <aggr_node1> -size 1TB   -security-style ntfs -junction-path /sql1_data    -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 1.3TB
volume create -vserver a50-sql -volume sql1_log     -aggregate <aggr_node2> -size 512GB -security-style ntfs -junction-path /sql1_log     -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_tempdb  -aggregate <aggr_node2> -size 500GB -security-style ntfs -junction-path /sql1_tempdb  -space-guarantee none -percent-snapshot-space 0 -snapshot-policy none -autosize-mode grow -max-autosize 650GB
volume create -vserver a50-sql -volume sql1_backups -aggregate <aggr_node1> -size 2000GB -security-style ntfs -junction-path /sql1_backups -space-guarantee none -percent-snapshot-space 5 -snapshot-policy none -autosize-mode grow -max-autosize 2600GB

# --- CA shares -----------------------------------------------------------
vserver cifs share create -vserver a50-sql -share-name sql1_data    -path /sql1_data    -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_log     -path /sql1_log     -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_tempdb  -path /sql1_tempdb  -share-properties oplocks,browsable,changenotify,continuously-available
vserver cifs share create -vserver a50-sql -share-name sql1_backups -path /sql1_backups -share-properties oplocks,browsable,changenotify,continuously-available

# --- Share permissions (repeat for each share) ----------------------------
vserver cifs share access-control create -vserver a50-sql -share sql1_data -user-or-group SAPCC\sql1admin -permission Full_Control
vserver cifs share access-control delete -vserver a50-sql -share sql1_data -user-or-group Everyone

# --- Verification ----------------------------------------------------------
vserver cifs show -vserver a50-sql
vserver cifs share show -vserver a50-sql -fields share-name,path,share-properties
vserver cifs session file show -vserver a50-sql -fields share,path,continuously-available
----

TIP: ボリュームを両ノードのアグリゲートに分散します。たとえば、データとバックアップはノード1に、ログとTempDBはノード2に配置します。これは両方のコントローラーのリソースを使用します。
