このソリューションは、Azure クラウドの ANF 上の Oracle デプロイメントのコンピューティングとストレージのサイズを決定するための便利なツールキットを提供します。



[[purpose]]
== 目的

既存の Oracle ワークロードを、オンプレミスからパブリック クラウドなど、あるプラットフォームから別のプラットフォームに移動する場合には、パフォーマンスとサービス レベルの要件を満たすように、ターゲット プラットフォームのコンピューティングとストレージのサイズを設定する必要があります。このドキュメントでは、その目標を達成するためのシンプルなツールキットを紹介します。

時間の経過とともに拡張される可能性のある新しいデータベース アプリケーションとは異なり、既存の Oracle ワークロードでは、コンピューティング要件とストレージ要件のワークロード パターンが確立されており、これは Oracle ワークロード リポジトリ (AWR) に記録されます。このツールキットは HTML パーサーを利用して Oracle AWR から関連情報を取得します。結果には、データベースに対する SQL スクリプトを通じて取得された追加のサイズ設定情報も補足され、Oracle データベースを再配置する際に役立つコンピューティングおよびストレージのガイダンスが提供されます。

このソリューションは、次のユースケースに対応します。

* オンプレミスから Microsoft Azure クラウドにデータベースを移行する場合の、Oracle データベース サーバー コンピューティングのサイズ設定に関するガイダンスを提供します。
* オンプレミスから Microsoft Azure NetApp Filesにデータベースを再配置する場合の Oracle データベース サーバー ストレージのサイズ設定に関するガイダンスを提供します。




[[audience]]
== 観客

このソリューションは次の人々を対象としています。

* オンプレミスのプライベート データ センターまたは Microsoft Azure クラウド環境で Oracle データベースを管理する DBA。
* Oracle データベースをサポートするオンプレミス ストレージまたは Microsoft Azure NetApp Filesストレージを管理するストレージ管理者。
* Oracle データベースをオンプレミスから Microsoft Azure クラウドに移行したいアプリケーション所有者。

[[how-to-use-the-toolkit]]
=== ツールキットの使い方は？

[%collapsible%open]
====
このツールキットは、Web ベースの HTML パーサーと、Oracle データベース情報を収集するための 2 つの SQL スクリプトで構成されています。次に、出力は Excel テンプレートに入力され、Oracle データベース サーバーのコンピューティングとストレージのサイズ設定ガイダンスが生成されます。

* 使用link:https://app.atroposs.com/#/awr-module["HTMLパーサー"^]AWR レポートから現在の Oracle データベースのサイズ情報を取得する AWR モジュール。
* DBA として ora_db_data_szie.sql を実行し、データベースから物理的な Oracle データ ファイル サイズを取得します。
* DBA として ora_db_logs_size.sql を実行し、必要なアーカイブ ログ保存期間 (日数) で Oracle アーカイブ ログのサイズを取得します。
* 上記で取得したサイズ情報を Excel テンプレート ファイル oracle_db_sizing_template_anf.xlsx に入力して、Oracle DB サーバーのコンピューティングとストレージに関するサイズ設定ガイダンスを作成します。


====


[[toolkit-usage-demonstration]]
=== ツールキットの使用デモンストレーション

[%collapsible%open]
====
. HTML パーサー AWR モジュールを開きます。
+
image:db-sizing-ora-parser-001.png["この画像はOracleのサイズ設定のためのHTMLパーサー画面を示しています"]

. 出力形式を.csvとしてチェックし、クリックします。 `Upload files` awr レポートをアップロードします。パーサーは、表の概要を含むHTMLページとoutput.csvファイルで結果を返します。 `Download`フォルダ。
+
image:db-sizing-ora-parser-002.png["この画像はOracleのサイズ設定のためのHTMLパーサー画面を示しています"]

. Excel テンプレート ファイルを開き、csv の内容を列 A のセル 1 にコピーして貼り付け、DB サーバーのサイズ情報を生成します。
+
image:db-sizing-ora-parser-anf-003.png["この画像は、Oracleのサイズ設定用のExcelテンプレートのスクリーンショットです。"]

. 列Aとフィールド1と2を強調表示し、クリックします `Data`、 それから `Text to Columns`テキストウィザードを開きます。選ぶ `Delimited`、 それから `Next`次の画面へ。
+
image:db-sizing-ora-parser-anf-004.png["この画像は、Oracleのサイズ設定用のExcelテンプレートのスクリーンショットです。"]

. チェック `Other`'='を次のように入力します `Delimiters`。クリック `Next`次の画面へ。
+
image:db-sizing-ora-parser-anf-005.png["この画像は、Oracleのサイズ設定用のExcelテンプレートのスクリーンショットです。"]

. クリック `Finish`読み取り可能な列形式への文字列変換を完了します。  VM および ANF のサイズ設定フィールドには、Oracle AWR レポートから取得されたデータが入力されていることに注意してください。
+
image:db-sizing-ora-parser-anf-006.png["この画像は、Oracleのサイズ設定用のExcelテンプレートのスクリーンショットです。"] image:db-sizing-ora-parser-anf-007.png["この画像は、Oracleのサイズ設定用のExcelテンプレートのスクリーンショットです。"]

. sqlplus で DBA としてスクリプト ora_db_data_size.sql、ora_db_logs_size.sql を実行し、保存期間の日数とともに既存の Oracle データベースのデータ サイズとアーカイブ ログのサイズを取得します。
+
....

[oracle@ora_01 ~]$ sqlplus / as sysdba

SQL*Plus: Release 19.0.0.0.0 - Production on Tue Mar 5 15:25:27 2024
Version 19.18.0.0.0

Copyright (c) 1982, 2022, Oracle.  All rights reserved.


Connected to:
Oracle Database 19c Enterprise Edition Release 19.0.0.0.0 - Production
Version 19.18.0.0.0


SQL> @/home/oracle/ora_db_data_size.sql;

Aggregate DB File Size, GiB Aggregate DB File RW, GiB Aggregate DB File RO, GiB
--------------------------- ------------------------- -------------------------
                     159.05                    159.05                         0

SQL> @/home/oracle/ora_db_logs_size.sql;
Enter value for archivelog_retention_days: 14
old   6:       where first_time >= sysdate - &archivelog_retention_days
new   6:       where first_time >= sysdate - 14

Log Size, GiB
-------------
        93.83

SQL>

....
+

NOTE: 上記のスクリプトを使用して取得されるデータベースのサイズ情報は、すべての物理データベース データ ファイルまたはログ ファイルの実際のサイズの合計です。各データ ファイル内で使用可能な空き領域は考慮されません。

. 結果を Excel ファイルに入力して、サイズ設定ガイダンスの出力を完了します。
+
image:db-sizing-ora-parser-anf-008.png["この画像は、Oracleのサイズ設定用のExcelテンプレートのスクリーンショットです。"]

. ANF は、3 層のサービス レベル (Standard、Premium、Ultra) を使用して、データベース ボリュームのスループット制限を管理します。参照link:https://learn.microsoft.com/en-us/azure/azure-netapp-files/azure-netapp-files-service-levels["Azure NetApp Filesのサービス レベル"^]詳細については。サイズ設定ガイダンスの出力に基づいて、データベースの要件を満たすスループットを提供する ANF サービス レベルを選択します。
