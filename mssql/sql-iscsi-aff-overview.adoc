= iSCSI LUNを使用したNetApp AFFでのSQL Server 2025について
:allow-uri-read: 


[role="lead"]
SQL Server 2025は、ONTAPを実行しているNetApp AFFシステムのiSCSI LUNにデータベースを保存できます。この構成の利点、解決策のコンポーネント、設計原則、パスやコントローラの障害時にマルチパスがデータベースをオンラインに保つ方法、およびNetApp Consoleのバックアップとリカバリがデータベースを保護する方法について説明します。

iSCSIは、SCSIブロックコマンドを標準的なTCP/IPイーサネットネットワーク上で転送します。WindowsとSQL Serverにとって、iSCSI LUNはローカルディスクです：初期化され、パーティション分割され、NTFSでフォーマットされ、ドライブ文字またはマウントポイントが割り当てられます。iSCSI経由のブロックストレージは、SQL Serverにおいて最も広く利用され、最もよく理解されているストレージオプションであり、SQL Serverのすべての機能とすべてのサードパーティ製ツールがこれをサポートしています。

AFFオールフラッシュ システム上のONTAPは、iSCSIをネイティブに実装しています。SQL Server 2025、Windows Server 2025、およびMicrosoft MPIOフレームワークと組み合わせることで、一貫して低遅延を実現し、パスやコントローラの障害を許容し、NetAppのデータ保護と統合するストレージ アーキテクチャを提供します。

この構成をデプロイするには、link:sql-iscsi-aff.html["iSCSI LUNを使用してNetApp AFFにSQL Server 2025をデプロイする"]を参照してください。



[[benefits-of-sql-server-on-iscsi-with-netapp-ontap]]
[[why]]
== NetApp ONTAP を使用した iSCSI 上の SQL Server の利点

[cols="1,3"]
|===
| 利点 | 概要 


| ユニバーサル互換性 | iSCSI LUNは、Windows用のローカルNTFSディスクです。SQL Server、そのツール、およびサードパーティ製アプリケーションは特別な設定を必要としません。ローカルサービスアカウントと仮想アカウントは通常どおり動作します。 


| 標準イーサネット | iSCSIは、データセンター内の既存のイーサネットネットワーク上で動作します。ファイバーチャネルファブリック、HBA、FCスイッチは不要です。 


| 高可用性 | MPIO と ALUA を使用すると、HA ペアの両方のノードへの複数のパスが使用されます。パス障害、ONTAP のテイクオーバー/ギブバック、無停止アップグレードは、Windows マルチパス ドライバによって透過的に処理されます。 


| パフォーマンス | AFFシステムは常に低遅延を実現します。複数のiSCSIセッションは、I/Oを複数のネットワークパスとポートに分散させます。 


| Storage Efficiency | シンプロビジョニング、インライン重複排除、圧縮、およびコンパクションにより、データベースとバックアップで使用される物理容量が削減されます。SCSI UNMAPは、解放されたブロックをアグリゲートに返します。 


| 統合データ保護 | ONTAPスナップショット、SnapRestore、FlexClone、およびSnapMirrorは、NetApp Consoleのバックアップおよびリカバリ機能によってオーケストレーションされ、数秒でのバックアップ、数分でのリストア、および瞬時のデータベースクローン作成を提供します。 


| オンライン容量管理 | ONTAPではボリュームとLUNをオンラインで拡張でき、WindowsではNTFSボリュームをオンラインで拡張できます。 
|===

== 解決策コンポーネント

この解決策は、以下の構成要素から成り立っています：

[cols="1,3"]
|===
| コンポーネント | ロール 


| Windows Server 2025 ホスト(`{host}`） | SQL Server 2025 を実行します。SQL Server のバイナリおよびシステム データベースはローカル ディスク `C:`に格納されており、ユーザー データベース、ログ、TempDB、およびログ バックアップは 4 つの NetApp LUN に格納されています。 


| Microsoft iSCSI イニシエータおよび MPIO | ホストをSVMのiSCSI LIFに接続し、各LUNへのパスを1つのマルチパスディスクに結合します。 


| SQL Server 2025 | データベース エンジン、デフォルト インスタンス `MSSQLSERVER`。 


| Active DirectoryとDNS | ドメインメンバーシップ、SQL Server管理者のWindows認証、名前解決、および時刻同期。 


| NetApp AFF A50 HAペア | 共有NVMeストレージを備えた2つのコントローラ。一方のコントローラが故障またはアップグレードされた場合、パートナー側がそのストレージを引き継ぎ、パートナー側のiSCSIパスがアクティブになります。 


| SVM `{svm}` | ノードごとに2つのiSCSI LIF、イニシエータグループ `{igroup}`、およびそれぞれ独自のFlexVol volumeに配置された4つのLUNを備えたiSCSIターゲットを提供します。 


| NetApp Consoleバックアップとリカバリ | アプリケーションと整合性のあるスナップショットバックアップを作成し、復元、クローン作成、およびレプリケーション機能を提供します。 
|===

[[design-principles]]
[[design]]
== 設計原則

この設計は、ONTAP SANストレージ上のSQL Serverに関するNetAppのベストプラクティスに従っています：

* *ファイルの種類ごとにLUNとボリュームを分ける。*データ、トランザクションログ、TempDB、およびログバックアップはそれぞれ別のLUNに配置され、各LUNは独自のFlexVol volumeに配置されます。各ボリュームは、それぞれ独自のサイズ、QoS、効率、スナップショット、およびレプリケーションの設定を持つことができ、データボリュームのスナップショットにTempDBが含まれることはありません。
* *ボリュームは両方のノードに分散されます。*データボリュームとバックアップボリュームはノード1に、ログボリュームとTempDBボリュームはノード2に配置されているため、両方のコントローラが有用な処理を実行できます。
* *ノードごとに2つのiSCSI LIF。*各LUNには4つの経路でアクセス可能です：LUNを所有するノードを経由する2つのアクティブ/最適化された経路と、HAパートナーを経由する2つのアクティブ/非最適化経路です。
* *Microsoft DSMを使用したMPIO。*NetApp Windows Host Utilitiesは、推奨タイムアウト値とマルチパスポリシーを設定します。
* *データベースボリューム上のシンプロビジョニング、およびスケジュールされたONTAPスナップショットがないこと。*バックアップはアプリケーション整合性が確保されている必要があります。これらはNetApp Consoleのバックアップとリカバリによって作成されます。
* *専用iSCSIネットワーク。*iSCSIには専用のNICまたはVLANを使用し、ジャンボフレーム（MTU 9000）をエンドツーエンドで構成してください。

== マルチパスがSQL Serverを保護する仕組み

ONTAPは非対称論理ユニットアクセス（ALUA）を使用して、ホストに最適なパスを指示します。LUNを所有するノードのiSCSI LIFを経由するパスは、*active/optimized*として報告されます。HAパートナーのLIFを経由するパスは、*active/non-optimized*として報告されます。これらのパスで送信されたI/Oは、クラスタ インターコネクト経由で転送されます。Microsoft DSMは、最適化されたパス（ポリシー*Round Robin with Subset*）でのみI/Oを送信し、最適化されていないパスはスタンバイとして保持します。

パスに障害が発生した場合、MPIOは残りの最適化されたパスで処理を続行します。所有ノードに障害が発生した場合、またはアップグレードのためにテイクオーバーされた場合、パートナーノードがアグリゲートをテイクオーバーし、ONTAPは新しいALUAの状態を報告し、MPIOはI/Oを新しい最適化されたパスに移動します。SQL ServerではI/O処理の一時停止が短時間発生するだけで、データベースはオンライン状態を維持します。

== NetApp Consoleバックアップとリカバリによるデータ保護

*NetApp Console*は、ストレージおよびデータサービス向けのNetAppの統合コントロール プレーンです。その*バックアップとリカバリ*サービスは、アプリケーション整合性のあるスナップショットを使用してONTAP上のMicrosoft SQL Serverデータベースを保護し、セカンダリONTAPシステムおよびオブジェクトストレージにレプリケートできます。



[[architecture]]
[[console-architecture]]
=== アーキテクチャ

この解決策は、以下の構成要素から成り立っています：

* *NetApp Console* （SaaS）：インベントリ、ポリシー、スケジュール、リストアとクローン、ジョブ監視、ロールベースのアクセス制御、および通知のためのWebインターフェース。
* *Consoleエージェント*：ConsoleをONTAPクラスタおよびSQL Serverホストと接続する、データセンター内のLinux VMです。アウトバウンドHTTPSのみを使用してConsoleと通信します。
* *SnapCenter SQL ServerおよびWindows向けプラグイン*：ConsoleによってSQL Serverホストにデプロイされます。インスタンスとそのデータベースを検出し、データベースファイルをNetApp LUNにマッピングして、バックアップ中にSQL Serverを静止させます。プラグインはポート8145でリッスンし、ホスト上にPowerShell 7と.NETを必要とします。
* *ONTAP*：ボリューム `sql_iscsi_1_data`および `sql_iscsi_1_log`のスナップショットを作成し、SnapRestoreおよびFlexClone処理を実行します。SQL Server自体は、iSCSI経由で引き続きファイルにアクセスします。


image::sql25_iscsi_bp_056.svg[iSCSI LUN上のSQL Server向けNetApp Consoleのバックアップおよびリカバリアーキテクチャ]



[[how-a-local-snapshot-backup-works]]
[[console-workflow]]
=== ローカルスナップショットバックアップの仕組み

. NetApp Consoleは、保護ポリシーでスケジュールされた、またはオンデマンドのバックアップ ジョブを開始します。
. プラグインは、SQL Server VDI/VSSインターフェイスを使用して、データベースの書き込みI/Oを数秒間停止します。
. ONTAPは、データボリュームとログボリュームの一貫性のあるスナップショットを作成します(`sql_iscsi_1_data`、 `sql_iscsi_1_log`）。データはコピーされません。
. データベースが再開され、バックアップはSQL Serverのバックアップ履歴(`msdb`）およびConsoleカタログに、その保持情報とともに記録されます。
. トランザクションログのバックアップは短い間隔（例えば15分ごと）で実行され、 `H:\backup`ポイントインタイム リカバリを可能にします。
. オプション：3-2-1バックアップ戦略のために、スナップショットはSnapMirrorを使用してセカンダリONTAPシステムにレプリケートされるか、オブジェクトストレージにバックアップされます。

=== SQL Server用NetApp Consoleの利点

* *バックアップは数秒で完了します。*スナップショットバックアップは、データベースの規模に関わらず数秒で完了し、バックアップウィンドウはほとんど不要になります。
* *パフォーマンスへの影響はありません。*ホスト上またはネットワーク上で、データの読み取りやコピーは一切行われません。SQL Serverはほんの数秒間だけ静止状態になります。
* *数分でリストアします。*データベースファイルはスナップショットからほぼ瞬時にリストアされます。ログバックアップと組み合わせることで、任意のポイントインタイムにリカバリできます。
* *省スペースなバックアップ。*スナップショットは変更されたブロックのみを保存するため、わずかな追加容量で多数のリストアポイントを保持できます。
* *瞬時にクローンを作成。*FlexCloneは、開発、テスト、レポート作成、トラブルシューティングのために、本番データベースの書き込み可能なコピーを数秒で作成します。データが変更されるまで、追加の容量は使用しません。
* *1つのポリシーによる3-2-1の保護。*ローカル スナップショット、セカンダリONTAPシステムへのレプリケーション、およびオブジェクト ストレージ（たとえば、NetApp StorageGRIDやパブリック クラウド）へのバックアップは、同じ保護ポリシーで構成されます。
* *維持すべきバックアップ インフラはありません。*コントロール プレーンはサービスとして提供され、軽量なConsoleエージェントのみがオンプレミスで実行されます。インストール、パッチ適用、保護が必要なバックアップサーバーやカタログデータベースは存在しません。
* *一元管理。*すべてのSQL Serverホストのインベントリ、ポリシー、スケジュール、保持、ロールベースのアクセス制御、ジョブ監視、および通知は、自動化のためのREST APIを備えた1つのWebインターフェイスで提供されます。
* *SnapCenterからのスムーズな移行。*既存のSnapCenter設定はNetApp Consoleにインポートできます。
* *ランサムウェアに対する耐性。*ONTAPスナップショットは読み取り専用ですが、特権ユーザーはロック解除されたスナップショットを削除できます。削除から保護するために、保持期間を設定したONTAPの改ざん防止スナップショットロックを使用し、サポートされている場合は自律型ランサムウェア対策と組み合わせてください。
