= Google Cloud NetApp Volumes の高可用性 Oracle Database 26ai をデプロイするためのワークフロー
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ../media/


[role="lead"]
Google Cloud NetApp Volumes の iSCSI ブロックストレージを使用して、Google Compute Engine 上に Oracle Data Guard を搭載した高可用性 Oracle Database 26ai をデプロイします。このワークフローでは、デプロイメントオプション、インフラストラクチャのプロビジョニング、Oracle ソフトウェアのインストール、および高可用性構成について手順を説明し、GCNV のストレージ層レプリケーションを活用してスタンバイ環境の初期化を高速化します。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-1.png["1"]link:gcnv-oracle-solution-architecture.html["ソリューション アーキテクチャの確認"]
[role="quick-margin-para"]
Oracle Database 26ai の高可用性を実現するための Google Cloud NetApp Volumes アーキテクチャについて説明します。GCNV iSCSI ブロックストレージ設計、Data Guard 統合、およびストレージトポロジーを含みます。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-2.png["2"]link:gcnv-oracle-deployment-options.html["導入オプションと要件を確認する"]
[role="quick-margin-para"]
デプロイメント ティアを開発とテストから本番環境の HA まで比較し、インフラストラクチャ、アクセス、およびソフトウェアの前提条件を確認します。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-3.png["3つ"]link:gcnv-oracle-access-and-apis.html["アクセスとAPIを確認する"]
[role="quick-margin-para"]
必要なアクセス権限、APIの有効化、ネットワークの前提条件、および時刻同期を確認してください。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-4.png["4"]link:gcnv-oracle-provision-compute.html["Google Compute Engine インスタンスをプロビジョニングする"]
[role="quick-margin-para"]
プライマリデータベース、スタンバイデータベース、および Fast-Start Failover Observer 用の VM を作成します。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-5.png["五"]link:gcnv-oracle-provision-storage.html["GCNV iSCSI ストレージをプロビジョニングする"]
[role="quick-margin-para"]
GCNV ストレージ プールと iSCSI ボリュームを作成し、マルチパスを構成し、ASM ディスク グループを設定します。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-6.png["六"]link:gcnv-oracle-install-software.html["Oracle Grid InfrastructureとOracle Database 26aiをインストールする"]
[role="quick-margin-para"]
両方のデータベースホストにOracle Grid InfrastructureとOracle Database 26aiソフトウェアをインストールします。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-7.png["セブン"]link:gcnv-oracle-primary-database.html["プライマリデータベースを作成する"]
[role="quick-margin-para"]
ASMストレージを使用してプライマリOracleデータベースを作成し、Oracle Restartを構成します。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-8.png["8"]link:gcnv-oracle-standby-database.html["スタンバイデータベースを作成する"]
[role="quick-margin-para"]
GCNVレプリケーション、スナップショット、またはクローンを使用してスタンバイデータベースを初期化し、Oracle Restart に登録します。すべての HA ティアでこの手順を完了します。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-9.png["9"]link:gcnv-oracle-standby-finalize-dg.html["Data Guard用のスタンバイデータベースを確定する"]
[role="quick-margin-para"]
スタンバイREDOログを作成し、フラッシュバックを有効にし、REDO転送をアクティブ化し、Data Guardの状態を確認します。*ティア固有：* Prod HA (Data Guard + FSFO) ティアでのみ必要です。

.image:https://raw.githubusercontent.com/NetAppDocs/common/main/media/number-10.png["10"]link:gcnv-oracle-data-guard.html["Data Guard BrokerとFast-Startフェールオーバーの設定"]
[role="quick-margin-para"]
ブローカーを有効にし、Data Guard 構成を作成し、FSFO を有効にし、オブザーバーを構成します。*ティア固有：* Prod HA (Data Guard + FSFO) ティアでのみ必要です。
