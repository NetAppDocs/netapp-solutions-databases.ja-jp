= iSCSI LUNを使用してNetApp AFFにSQL Server 2025をデプロイする
:allow-uri-read: 


[role="lead"]
NetApp AFFシステム上のiSCSI LUNにユーザー データベース、トランザクション ログ、TempDB、およびログ バックアップを配置して、SQL Server 2025をWindows Server 2025にデプロイします。この手順には、ONTAP SVMでのiSCSIの構成、イニシエータ グループとLUN、Windows iSCSIイニシエータ、MPIOとディスクの構成、およびSQL Serverのインストールが含まれます。



[[scope]]
[[intro-scope]]
== Scope

この手順では、単一のWindows Server 2025ホスト上にスタンドアロンのSQL Server 2025インスタンスをデプロイし、ユーザーデータベース、トランザクションログ、TempDB、およびログバックアップをiSCSI LUN上に配置します。同じストレージ設計は、SQL Serverフェールオーバークラスターインスタンス（FCI）およびAlways On可用性グループにも適用されますが、クラスター固有の構成については説明しません。SQL Serverのパフォーマンスチューニングとサイジングも対象外です。利点、解決策のコンポーネント、設計原則、マルチパスの仕組みの説明、およびNetApp Console Backup and Recoveryを使用したデータ保護については、link:sql-iscsi-aff-overview.html["iSCSI LUNを使用したNetApp AFFでのSQL Server 2025について"]を参照してください。



[[audience]]
[[intro-audience]]
== 観客

この手順の対象者は次のとおりです：

* ONTAPクラスタ、SVM、iSCSI LIF、イニシエータグループ、およびLUNを設定する*ストレージ管理者*。
* Windows Server 2025 ホスト、iSCSI イニシエータ、MPIO、およびディスクを準備する *Windows 管理者*。
* *データベース管理者*は、SQL Server 2025をインストールおよび構成し、バックアップとリカバリを設定します。


ONTAP System Manager、Windows Server、およびSQL Serverの管理に関する基本的な知識があることを前提としています。

[[overview]]

この手順で使用したスクリーンショットは、以下の実験環境で撮影されたものです。お使いの環境の値に置き換えてください。

| Active Directoryドメイン | `{domain}` (`{fqdn-domain}`） 


| SQL Serverホスト | `{host}.{fqdn-domain}`、Windows Server 2025 Datacenter （デスクトップ エクスペリエンス） 


| ホストiSCSIイニシエータ | `{init-iqn}`、iSCSI IPアドレス 192.168.175.44 


| イニシエータグループ | `{igroup}`、ホストOS *Windows* 


| SQLサーバ | SQL Server 2025 Enterprise Edition、デフォルトインスタンス `MSSQLSERVER` 
|===
[cols="2,2,1,1,2"]
|===
| LUN | Volume | サイズ | ドライブ | 内容 


| `sql_iscsi_1_data_1` | `sql_iscsi_1_data` | 520 GiB | `E:`（データ） | ユーザーデータベースデータファイル(`.mdf`、 `.ndf`）内の `E:\data` 


| `sql_iscsi_1_log_1` | `sql_iscsi_1_log` | 250 GiB | `F:` （log） | ユーザー データベース トランザクション ログ ファイル(`.ldf`）内の `F:\log` 


| `sql_iscsi_1_tempdb_1` | `sql_iscsi_1_tempdb` | 150 GiB | `G:`（tempdb） |  `G:\tempdb\data`および `G:\tempdb\log`内のTempDBデータとログファイル

TIP: ボリュームごとに1つのLUNを使用し、データ、ログ、TempDB、バックアップ用にそれぞれ別のボリュームを使用してください。これにより、ボリュームごとに異なるQoS、スナップショット、効率性、およびレプリケーション設定を適用できます。また、常に変化するTempDBをユーザーデータベースのスナップショットから除外します。


TIP: 負荷分散のため、別のコントローラで追加のLUNを使用して、追加のセカンダリデータファイル（.ndf）を配置してください。



[[prerequisites]]
== 前提条件

開始する前に、以下の要件を満たしていることを確認してください：

.NetApp ONTAP
* AFF HAペアがインストールされ、クラスターがセットアップされ、正常に動作しています。
* iSCSIライセンスがインストールされています。ONTAP Oneに含まれています。
* 各ノードに少なくとも1つのデータ アグリゲート（ローカル層）が存在します。
* SVMは存在します。この手順では、既存のSVM `{svm}`を使用し、そこにiSCSIを追加します。SAN専用のSVMを作成するには、menu:Cluster[Storage VMs > Add]を使用し、アクセス プロトコルとして*iSCSI*を選択します。
* iSCSI LIF用のデータネットワークポート、ブロードキャストドメイン、および（オプションで）VLANが設定されます。ラボでは、ブロードキャストドメイン `MT9000`でジャンボフレームを使用します。
* クラスタ、ホスト、およびActive Directory間の時刻は、NTPを介して同期されます。


.Network
* SQL Serverホストには、iSCSIサブネットまたはVLAN内に、iSCSI専用のNICが少なくとも1つ、できれば2つ必要です。
* MTUはエンドツーエンド（ホストNIC、スイッチ、ONTAPポート）で同じです。ホストから `ping -f -l 8972 <LIF-IP>`を使用してジャンボフレームを確認します。


.Windows Server
* Windows Server 2025（デスクトップエクスペリエンス）がインストールされ、パッチが適用され、ドメインに参加しています。
* Windows Server 2025 でサポートされているバージョンの NetApp Windows Host Utilities が利用可能です（ https://imt.netapp.com/matrix/["NetApp Interoperability Matrix Tool（IMT）"^]を参照してください）。
* SQL Server 2025のインストールメディア（ISO）と有効なプロダクトキー（または無料版）をご用意ください。



NOTE: SMBファイル共有とは異なり、LUNではSQL Serverサービスにドメインアカウントは必要ありません。デフォルトの仮想アカウント(`NT Service\MSSQLSERVER`）を使用できます。インスタンスがネットワーク アクセスを必要とする場合（たとえば、ファイル共有へのバックアップやKerberos認証など）、引き続きドメインアカウントまたはgMSAの使用が推奨されます。



[[step-1-enable-iscsi-on-the-storage-vm]]
[[svm-iscsi]]
== ステップ1：ストレージVMでiSCSIを有効にする

SVMにiSCSIプロトコルを追加し、HAペアの各ノードに2つのiSCSI LIFを作成します。

.手順
. SVM上でiSCSIを有効にし、System ManagerまたはCLIを使用してiSCSI LIFを作成します：
+
[role="tabbed-block"]
====
.System Manager
--
.. Webブラウザを開き、 `+https://<cluster-management-IP>+`でONTAP System Managerに接続します。クラスタ管理者アカウントでログインします。
.. menu:Cluster[Storage VMs]に移動し、SVM `{svm}`をクリックして、*設定*タブを開きます。*プロトコル*の下にある*iSCSI*タイルには、*未構成*と表示されます。*iSCSI*タイルの歯車アイコンをクリックします。
+
.例を表示
[%collapsible]
=====
image:sql25_iscsi_bp_004.png["iSCSIが構成されていないストレージVM a50-sqlの設定、width=800"]

=====
.. *iSCSIの構成*ダイアログで、iSCSIネットワーク インターフェイスを作成します。System Managerは、ノードごとに2つのネットワーク インターフェイスを推奨しています。以下の値を入力してください：
+
*** ノード `{node1}`：IPアドレス `192.168.175.134`、サブネットマスク `24`、*ブロードキャストドメインとポート* `MT9000`
*** *「以下のすべてのインターフェイスで同じサブネットマスク、ゲートウェイ、およびブロードキャストドメインを使用する」*を選択します。
***  `{node1}`上の2番目のインターフェイス： `192.168.175.135`
*** ノード `{node2}`： `192.168.175.136` および `192.168.175.137`
+
*保存*をクリックします。

+

TIP: ホストとLIFが同じサブネット内にある場合、ゲートウェイは不要です。iSCSIトラフィックをルーティングしないでください。

+
.例を表示
[%collapsible]
=====
image:sql25_iscsi_bp_005.png["ノードごとに2つのLIFを使用したiSCSIの設定ダイアログ、width=800"]

=====


.. System ManagerはiSCSIサービスと4つのLIFを作成します。*iSCSI*タイルに*有効*、*ターゲットノード名*(`{tgt-iqn}`）、および*ターゲットエイリアス* `{svm}`が表示されるようになります。ターゲットノード名をメモしておいてください。ホストからの接続を確認する際に必要になります。
+
.例を表示
[%collapsible]
=====
image:sql25_iscsi_bp_006.png["ターゲットノード名とエイリアスで有効化されたiSCSI、width=800"]

=====


--
.ONTAP CLI
--
以下のコマンドは、CLIから同じ設定を作成します。山括弧内のプレースホルダー値を置き換えてください。 `vserver iscsi show`の出力にあるターゲット名に注意してください。ホストからの接続を確認するために必要です。

[source, console]
----
cluster::> vserver add-protocols -vserver a50-sql -protocols iscsi
cluster::> vserver iscsi create -vserver a50-sql -target-alias a50-sql

cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_1 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.134 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
cluster::> network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

cluster::> vserver iscsi show -vserver a50-sql
cluster::> network interface show -vserver a50-sql -data-protocol iscsi
----
--
====



NOTE: iSCSI LIFは、テイクオーバー中に移行しません。パートナーノードのLIFへのパスが高可用性を提供するため、HAペアの両方のノードにiSCSI LIFを必ず作成してください。

IMPORTANT: LUNに接続する*前*に、MPIOをインストールして設定してください。MPIOを使用しない場合、Windowsは各LUNへのパスごとに1つのディスクを表示します（この構成では、LUNごとに4つのディスクが表示されます）。

+
.例を表示
[%collapsible]
=====
image:sql25_iscsi_bp_008.png["Microsoft iSCSIサービスが実行されていないダイアログ、width=800"]

=====
.. *iSCSIイニシエータのプロパティ*で、*構成*タブを開きます。*イニシエータ名*をコピーします(`{init-iqn}`）。ONTAPでイニシエータグループを作成するために必要です。
+
.例を表示
[%collapsible]
=====
image:sql25_iscsi_bp_009.png["iSCSIイニシエータのプロパティ構成タブ、イニシエータ名、幅=800"]

--

PS C:\> (Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress
----
--
====
. Server ManagerまたはPowerShellを使用して、マルチパスI/Oをインストールし、iSCSIデバイスのMPIOサポートを有効にします：
+
[role="tabbed-block"]
====
.サーバーマネージャー
--
.. *サーバーマネージャー*で、menu:管理[役割と機能の追加]をクリックします。*機能*ページで、*マルチパスI/O*を選択し、*インストール*をクリックします。

.例を表示

image:sql25_iscsi_bp_010.png["役割と機能の追加ウィザード 機能の選択ページ,width=800"]

+
再起動後、チェックボックスがオンになりグレー表示になります。これは、MPIO がすべての iSCSI デバイスを管理することを意味します。LUN が接続されると（<<connect>>を参照）、 `Get-Disk`は、PowerShell ウィンドウに示されているように、各 NetApp LUN を 1 回だけ表示します。

.例を表示
[%collapsible]

image:sql25_iscsi_bp_011.png["MPIOプロパティ iSCSIサポートとGet-Disk出力によるマルチパスの検出、width=800"]

--
.PowerShell
--

----

----

====

.手順
. System ManagerまたはCLIを使用してイニシエータグループを作成します：
+
[role="tabbed-block"]

.例を表示

*** *ストレージVM*： `{svm}`
*** *イニシエータグループのメンバー*：*ホストイニシエータ*
*** *iSCSIイニシエータ* > *新規イニシエータ*：ホストのイニシエータ名を貼り付け、 `{init-iqn}`

[[step-4-create-the-sql-server-luns]]
[[luns]]
== ステップ4：SQL Server LUNを作成する

ファイルの種類ごとに1つのLUNを作成します。System Managerは、*名前プレフィックス*にちなんで名付けられたFlexVol volumeと、サフィックス `_1`が付いたLUNを作成し、そのLUNを選択したigroupにマッピングします。

.手順
. System ManagerまたはCLIを使用して、データ、ログ、TempDB、およびログバックアップLUNを作成します：
+
[role="tabbed-block"]
====
.System Manager
--
.. System Managerで、*ストレージ*を展開し、*LUNs*をクリックします。
+
.例を表示
[%collapsible]
=====
image:sql25_iscsi_bp_016.png["LUNが選択されたストレージメニュー、width=800"]

=====
.. *+ 追加*をクリックし、データLUNに以下の値を入力します：
+
*** *名前の接頭辞*： `sql_iscsi_1_data`
*** *ストレージVM*： `{svm}`
*** *LUNの数*： `1`、*LUNあたりの容量*： `520 GiB`
*** *パフォーマンスサービスレベル*：*カスタム*、*QoSポリシーグループの割り当て*：*既存* > `none`
*** *保護*：*スナップショットを有効にする（ローカル）*および*SnapMirrorを有効にする（ローカルまたはリモート）*はクリアしたままにします。アプリケーション整合性バックアップは、NetApp Console Backup and Recoveryが作成します（link:sql-iscsi-aff-overview.html#console["NetApp Consoleバックアップとリカバリによるデータ保護"]を参照）。
*** *ホスト情報*：*ホストオペレーティングシステム* *Windows*、*LUN形式* *Windows 2008*（この形式は、Windows Server 2008以降のすべてのWindowsバージョン（Windows Server 2025を含む）で有効です）
*** *ホストマッピング*：*既存のイニシエータグループ*、選択 `{igroup}`
+
*保存*をクリックします。

+

TIP: ボリュームを作成するノードを制御するには、*手動配置*を選択し、ローカルティアを選択します。データボリュームとバックアップボリュームをノード1に、ログボリュームとTempDBボリュームをノード2に配置します。

+
.例を表示
[%collapsible]
=====
image:sql25_iscsi_bp_017.png["520 GiB データ LUN 用の LUN 追加ダイアログ,width=600"]

=====


.. メッセージ *The LUNs were added* が表示され、LUN `sql_iscsi_1_data_1`がボリューム `sql_iscsi_1_data`に表示されます。
.. ログ、TempDB、およびログバックアップLUNについて、<<overview>>に記載されている名前とサイズでこれらの手順を繰り返します。
.. これで、4つのLUNすべてがSVM `{svm}`上に作成され、igroup `{igroup}`にマッピングされました。
+
.例を表示

[[step-5-review-the-volume-and-lun-settings]]
[[volume-settings]]
== ステップ5：ボリュームとLUNの設定を確認する

4つのボリュームのスペース設定とスナップショット設定を確認してください。System Managerは適切なデフォルト値を使用します。SQL Server LUNには以下の設定が推奨されます：

[cols="1,1,3"]
|===
| 設定 | Value | 理由 


| スペース保証（ボリューム） | `none`（シン） | 容量はデータの書き込み時にのみ消費されます。 


| LUNスペース リザベーション | `disabled`（シン） | シンボリューム内のシンLUN。 


| LUN スペース割り当て | `enabled` | SCSI UNMAPを有効にして、NTFSで解放された領域がONTAPに返されるようにし、ボリュームの空き容量が不足したときにホストが正しく反応できるようにします。 


| スナップショットポリシー | `none` | アプリケーションと整合性のないスナップショットは、SQL Serverでは役に立ちません。バックアップは、NetApp Consoleのバックアップとリカバリによって作成されます。 


| Snapshotリザーブ | `0` % | Snapshotスペースは、代わりにボリュームの自動調整で監視されます。 


| 自動サイズ調整 | `grow`、最大でボリュームサイズの約130% | スナップショットが容量を消費する際に、LUNがオフラインになるのを防ぎます。 


| Storage Efficiency | 有効（AFFではデフォルト） | インライン重複排除、圧縮、およびコンパクションは、SQL Serverのパフォーマンスに測定可能な影響を与えません。 
|===
以下のコマンドを使用して設定を適用および確認します（ `sql_iscsi_1_data` の場合）：

[source, console]
----
cluster::> volume modify -vserver a50-sql -volume sql_iscsi_1_data -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
cluster::> lun modify -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1 -space-allocation enabled
cluster::> volume show -vserver a50-sql -volume sql_iscsi_1_* -fields aggregate,size,space-guarantee,snapshot-policy,autosize-mode
----

NOTE: 既存のLUNで `space-allocation`を変更するには、LUNをオフラインにする必要があります。作成時、またはホストがLUNに接続する前に設定してください。

.PowerShell
--
以下のコマンドはNetAppディスクをオンラインにして、GPTで初期化し、それぞれに64Kのアロケーションユニットサイズを持つNTFSボリュームを1つ作成してフォーマットし、SQL Server用のフォルダを作成します。

[source, powershell]
----
PS C:\> $layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
PS C:\> foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
          $l = $layout[[int64]$d.Size]
          Set-Disk -Number $d.Number -IsOffline $false
          Set-Disk -Number $d.Number -IsReadOnly $false
          Initialize-Disk -Number $d.Number -PartitionStyle GPT
          New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
            Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
        }
PS C:\> 'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ }
PS C:\> Get-Volume -DriveLetter E,F,G,H | Format-Table DriveLetter,FileSystemLabel,FileSystem,AllocationUnitSize,Size
----

CAUTION: これらのコマンドは、これらの LUN がシステムに接続されている唯一の RAW LUN である場合にのみ実行してください。システムに他の RAW LUN が接続されている場合は、手動でフォルダを作成してボリュームをフォーマットする必要があります。

[[step-9-verify-the-installation]]
[[post-install]]
== ステップ9：インストールを確認する

テストデータベースを作成し、そのデータファイルとログファイルがNetApp LUN上にあること、およびストレージパスが正常であることを確認します。

.手順
. WindowsファイアウォールでSQL Serverのポートを開放してください：
+
[source, powershell]
----
PS C:\> New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----
. インストールセンターの「SQL Server 管理ツールのインストール」リンク、またはMicrosoftのWebサイトから、SQL Server Management Studio (SSMS) をインストールしてください。
. SSMSを起動し、Windows認証を使用してインスタンス (`{host}`）に接続します。テストデータベースを作成します。データファイルとログファイルはデフォルトで `E:\data`および `F:\log`になります。
. T-SQLを使用してファイルの場所を確認します：
+
[source, sql]
----
SELECT DB_NAME(database_id) AS database_name,
       type_desc,
       name AS logical_name,
       physical_name,
       size * 8 / 1024 AS size_mb
FROM   sys.master_files
ORDER  BY database_id, type_desc;
----
. インスタントファイル初期化が有効になっていることを確認してください：
+
[source, sql]
----
SELECT servicename, service_account, instant_file_initialization_enabled
FROM   sys.dm_server_services;
----
. ホストおよびONTAPからストレージを確認します：
+
[source, powershell]
----
PS C:\> Get-Disk | Where-Object FriendlyName -like 'NETAPP*' | Format-Table Number,FriendlyName,Size,OperationalStatus,PartitionStyle
PS C:\> mpclaim -s -d
----
+
[source, console]
----
cluster::> lun show -vserver a50-sql -fields path,size,mapped,state
cluster::> vserver iscsi session show -vserver a50-sql
cluster::> qos statistics volume latency show -vserver a50-sql
----
. オプション：高可用性をテストします。テストデータベースに対してワークロードを実行し、データボリュームを所有するノードのONTAPテイクオーバーとギブバックを実行します(`storage failover takeover -ofnode <node>` / `storage failover giveback -ofnode <node>`）。ワークロードは数秒間一時停止したあと再開し、データベースはオンライン状態を維持します。


.次の手順
アプリケーション整合性スナップショットバックアップでデータベースを保護します。アーキテクチャ、バックアップワークフロー、およびメリットについては、link:sql-iscsi-aff-overview.html#console["NetApp Consoleバックアップとリカバリによるデータ保護"]を参照してください。



[[use-an-ontap-cli-script-to-configure-the-storage-in-one-pass]]
[[cli-script]]
== ONTAP CLIスクリプトを使用して、ストレージを一度に構成します

以下のスクリプトには、この手順で取得したストレージ構成がすべて含まれています。実行する前に、山括弧内の値を置き換えてください。

[source, console]
----
# --- iSCSI service and LIFs ----------------------------------------------
vserver add-protocols -vserver a50-sql -protocols iscsi
vserver iscsi create -vserver a50-sql -target-alias a50-sql

network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_1 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.134 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n1_2 -service-policy default-data-iscsi -home-node SAPCC-A50-01 -home-port <port> -address 192.168.175.135 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_1 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.136 -netmask 255.255.255.0
network interface create -vserver a50-sql -lif a50-sql_iscsi_n2_2 -service-policy default-data-iscsi -home-node SAPCC-A50-02 -home-port <port> -address 192.168.175.137 -netmask 255.255.255.0

# --- Initiator group -----------------------------------------------------
lun igroup create -vserver a50-sql -igroup sql-iscsi-1 -protocol iscsi -ostype windows -initiator iqn.1991-05.com.microsoft:sql-iscsi-1.sapcc.stl.netapp.com

# --- Volumes -------------------------------------------------------------
volume create -vserver a50-sql -volume sql_iscsi_1_data      -aggregate <aggr_node1> -size 560GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 730GB
volume create -vserver a50-sql -volume sql_iscsi_1_log       -aggregate <aggr_node2> -size 270GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 350GB
volume create -vserver a50-sql -volume sql_iscsi_1_tempdb    -aggregate <aggr_node2> -size 165GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 210GB
volume create -vserver a50-sql -volume sql_iscsi_1_logbackup -aggregate <aggr_node1> -size 325GB -space-guarantee none -snapshot-policy none -percent-snapshot-space 0 -autosize-mode grow -max-autosize 420GB

# --- LUNs ----------------------------------------------------------------
lun create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -size 520GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -size 250GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -size 150GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled
lun create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -size 300GB -ostype windows_2008 -space-reserve disabled -space-allocation enabled

# --- LUN mapping ---------------------------------------------------------
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_data/sql_iscsi_1_data_1           -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_log/sql_iscsi_1_log_1             -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_tempdb/sql_iscsi_1_tempdb_1       -igroup sql-iscsi-1
lun mapping create -vserver a50-sql -path /vol/sql_iscsi_1_logbackup/sql_iscsi_1_logbackup_1 -igroup sql-iscsi-1

# --- Verification ----------------------------------------------------------
vserver iscsi show -vserver a50-sql
network interface show -vserver a50-sql -data-protocol iscsi
lun show -vserver a50-sql -fields path,size,ostype,space-allocation,mapped,state
lun mapping show -vserver a50-sql
vserver iscsi session show -vserver a50-sql
----

TIP: ボリュームを両ノードのアグリゲートに分散します。たとえば、データとログのバックアップはノード1に、ログとTempDBはノード2に配置します。これにより、両方のコントローラーのリソースが使用されます。



[[use-a-powershell-script-to-configure-the-host-in-one-pass]]
[[ps-script]]
== PowerShellスクリプトを使用して、ホストを一度に構成する

以下のスクリプトには、この手順の完全なホスト構成が含まれています。管理者権限のPowerShellセッションで実行してください。MPIO部分には再起動が必要です。

[source, powershell]
----
# --- Part 1: iSCSI service and MPIO (restart required) ------------------------
Set-Service -Name MSiSCSI -StartupType Automatic
Start-Service -Name MSiSCSI
(Get-InitiatorPort | Where-Object ConnectionType -eq 'iSCSI').NodeAddress   # initiator IQN for the igroup
Install-WindowsFeature -Name Multipath-IO
Enable-MSDSMAutomaticClaim -BusType iSCSI
# Install NetApp Windows Host Utilities (MPIO support) now, then:
Restart-Computer

# --- Part 2: connect the iSCSI sessions (after the LUNs are mapped in ONTAP) ---
$initiatorIP = '192.168.175.44'
$lifs        = '192.168.175.134','192.168.175.135','192.168.175.136','192.168.175.137'
New-IscsiTargetPortal -TargetPortalAddress $lifs[0] -InitiatorPortalAddress $initiatorIP
$target = Get-IscsiTarget | Where-Object NodeAddress -like 'iqn.1992-08.com.netapp:*'
foreach ($lif in $lifs) {
    Connect-IscsiTarget -NodeAddress $target.NodeAddress -TargetPortalAddress $lif `
        -InitiatorPortalAddress $initiatorIP -IsMultipathEnabled $true -IsPersistent $true
}
Get-IscsiSession | Format-Table TargetNodeAddress,InitiatorPortalAddress,IsConnected,IsPersistent
mpclaim -s -d

# --- Part 3: disks, volumes and folders ---------------------------------------
$layout = @{ 520GB = 'E','data'; 250GB = 'F','log'; 150GB = 'G','tempdb'; 300GB = 'H','Log backup' }
foreach ($d in Get-Disk | Where-Object FriendlyName -like 'NETAPP*') {
    $l = $layout[[int64]$d.Size]
    Set-Disk -Number $d.Number -IsOffline $false
    Set-Disk -Number $d.Number -IsReadOnly $false
    Initialize-Disk -Number $d.Number -PartitionStyle GPT
    New-Partition -DiskNumber $d.Number -UseMaximumSize -DriveLetter $l[0] |
        Format-Volume -FileSystem NTFS -AllocationUnitSize 65536 -NewFileSystemLabel $l[1] -Confirm:$false
}
'E:\data','F:\log','G:\tempdb\data','G:\tempdb\log','H:\backup' | ForEach-Object { New-Item -ItemType Directory -Path $_ -Force }

# --- Part 4: firewall for SQL Server -----------------------------------------
New-NetFirewallRule -DisplayName "SQL Server (TCP 1433)" -Direction Inbound -Protocol TCP -LocalPort 1433 -Action Allow
----

NOTE: 各パートを別々に実行してください。パート1ではホストの再起動が必要になるため、再起動後に他のパートは続行されません。


CAUTION: これらのLUNがシステムに接続されている唯一のRAW LUNである場合にのみ、パート3のコマンドを実行してください。システムに他のRAW LUNが接続されている場合は、フォルダを手動で作成し、ボリュームをフォーマットする必要があります。
